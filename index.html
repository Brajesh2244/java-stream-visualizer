Lazy Evaluation & Short-Circuiting Lab

Intermediate operations are lazy: they do zero work upon declaration. Work is only pulled element-by-element when a terminal operation demands it.

List<Integer> numbers = List.of(10, 20, 30, 40, 50);
numbers.stream()
.filter(n -> n > 20) // Lazy intermediate
.map(n -> n * 2) // Lazy intermediate
.findFirst(); // Terminal (Pulls first matching element!)
0 / 5 Elements Inspected
0 filter() Invocations
0 map() Invocations

⚡ Why Lazy Evaluation Matters

Unlike eager collections where each operation loops through all items, Streams combine operations into a single element-by-element pass.

  • Zero wasted computations: Elements 40 and 50 are never touched.
  • Zero intermediate buffers: No temporary lists created on heap.
  • Infinite streams possible: Bounded terminal ops like findFirst() or limit() can safely process infinite streams.

Traditional Loop vs Stream API

Compare imperative for loop iteration with declarative Stream pipeline processing side-by-side.

❌ Traditional For Loop (Imperative)

Explicit Iteration
List<Integer> result = new ArrayList<>();
for (Integer n : numbers) {
  if (n > 20) {
    result.add(n * 2);
  }
}
Execution Steps:
Key Characteristic: Tells the computer HOW to step through data with explicit mutable loops.

✅ Java Stream API (Declarative)

Declarative Pipeline
List<Integer> result = numbers.stream()
  .filter(n -> n > 20)
  .map(n -> n * 2)
  .toList();
Pipeline Stages:
Key Characteristic: Tells the computer WHAT transformation is required; internal engine optimizes traversal.

The Golden Stream Rule

Streams don't store data. They process data from a source through a pipeline.
